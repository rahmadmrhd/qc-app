## 1. Ringkasan

QC App dapat **dipasang di layar utama ponsel dan komputer** (Android, iOS, desktop) dan terbuka seperti aplikasi: ikon sendiri, tanpa bilah alamat, dan **mulai lebih cepat pada kunjungan berikutnya** karena cangkang aplikasi (HTML, JS, CSS) tersimpan di perangkat. Data tetap selalu diambil dari server; PWA tidak menjadikan aplikasi bekerja offline penuh.

Pekerjaan dibagi dua fase:

- **Fase 1 (disetujui):** dapat dipasang + cangkang aplikasi di-cache + pembaruan versi yang jelas. Tidak mengubah perilaku data.
- **Fase 2 (usulan, menunggu konfirmasi §11):** ketahanan saat server atau jaringan tidak tersedia: spanduk "data terakhir", dan antrean centang di perangkat yang terkirim otomatis saat server pulih.

## 2. Latar Belakang & Tujuan

### 2.1 Kondisi sekarang
Aplikasi web ini dilayani server Bun di VPS (HTTPS lewat nginx, satu origin) dengan aset statis berpotongan (lazy load per rute). Belum ada manifest, ikon aplikasi, maupun service worker. Pengguna (8–10 orang, sebagian memakai ponsel di gudang/QC) membuka aplikasi lewat bilah alamat peramban. Frontend sudah menyimpan sebagian data referensi di `localStorage` (`app/query-persist.ts`: `auth/me`, merk, QR; maks. 12 jam) dan memakai pembaruan optimistis untuk centang (`usePendingIds`, antrean serial per task).

### 2.2 Tujuan
- **G1.** Pengguna memasang aplikasi dengan satu langkah dan membukanya dari ikon di layar utama.
- **G2.** Kunjungan berikutnya terbuka cepat: cangkang aplikasi dari cache perangkat, tanpa menunggu unduhan ulang.
- **G3.** Setelah ada versi baru, pengguna tidak terjebak di cangkang lama yang kontrak API-nya sudah berubah: ada pemberitahuan dan satu klik untuk memuat versi baru.
- **G4.** (Fase 2) Gangguan server sementara (mis. kuota harian basis data habis, `UNAVAILABLE`) tidak membuat layar kosong atau centang hilang diam-diam.
- **G5.** Tidak menambah beban server (CPU atau kueri database) dan tidak melemahkan keamanan sesi atau pencabutan akses.

### 2.3 Non-goals
- Bukan aplikasi offline penuh: data (task, item, audit) tidak dapat dibuat atau dibaca tanpa server pada Fase 1.
- Tidak ada Background Sync, share target, atau pintasan aplikasi. **Notifikasi push dikecualikan dari non-goal ini sejak 2026-11-12** (keputusan pemilik): push dikerjakan sebagai proyek terpisah, `docs/superpowers/specs/2026-11-12-notifikasi-serah-terima-design.md`, dan bergantung pada Fase 1 PRD ini (service worker dan aplikasi terpasang). Fase 1 tidak berubah dan tidak memuat kode push.
- Tidak mem-cache respons `/api/*`, `/auth/*`, atau `/sync` di service worker.
- Tidak ada toko aplikasi (Play Store/App Store) atau pembungkus native.
- Tidak mengubah alur login Google atau masa berlaku sesi.

## 3. Pengguna & Peran

Tidak ada modul izin baru: PWA hanya mengemas aplikasi yang sama dan tidak menambah kemampuan data. Semua izin tetap ditegakkan server pada setiap permintaan (`server/src/core/router.ts`).

## 4. Kebutuhan Fungsional

### 4.1 Pemasangan (Fase 1)
| ID | Kebutuhan | Kriteria penerimaan |
|---|---|---|
| FR-P1 | Manifest aplikasi | `/manifest.webmanifest` valid: `name` "QC App", `short_name` "QC", `lang` `id`, `start_url` `/`, `scope` `/`, `display` `standalone`, `theme_color` dan `background_color` selaras tema |
| FR-P2 | Ikon | PNG 192 × 192 dan 512 × 512, ikon `maskable` 512 × 512, `apple-touch-icon` 180 × 180, favicon; tampil benar di layar utama Android dan iOS |
| FR-P3 | Warna bilah sistem mengikuti tema | `<meta name="theme-color">` berubah terang/gelap sesuai tema aktif (kelas `dark` di `<html>`), termasuk saat tema diganti di dalam aplikasi |
| FR-P4 | Dapat dipasang | Android Chrome menawarkan pemasangan (atau "Tambahkan ke layar utama"); iOS Safari "Tambahkan ke Layar Utama" menghasilkan aplikasi mandiri (`standalone`) yang membuka halaman aplikasi, bukan peramban |
| FR-P5 | Ajakan pasang opsional | Bila peramban mendukung `beforeinstallprompt`, menu pengguna memuat butir "Pasang aplikasi"; tidak ada pop-up yang mengganggu. Di iOS, butir yang sama menampilkan petunjuk singkat |

### 4.2 Cangkang aplikasi dan service worker (Fase 1)
| ID | Kebutuhan | Kriteria penerimaan |
|---|---|---|
| FR-P6 | Pra-cache cangkang | Service worker `/sw.js` (scope `/`) menyimpan `index.html` dan potongan JS/CSS/ikon hasil build (nama berhash) saat pemasangan; kunjungan berikutnya tidak mengunduh ulang berkas yang tidak berubah |
| FR-P7 | Navigasi rute klien | Membuka alamat rute (`/handover`, refresh, bookmark) saat jaringan lambat atau mati tetap memuat cangkang dari cache, lalu aplikasi menampilkan keadaan galat jaringan sendiri |
| FR-P8 | Jalur dinamis tidak pernah dilayani dari cache | Permintaan `/api/*`, `/auth/*`, `/sync` selalu ke jaringan; navigasi ke `/auth/*` (callback OAuth) TIDAK pernah dijawab `index.html` oleh service worker |
| FR-P9 | Potongan berat dimuat sesuai kebutuhan | Potongan besar yang jarang dipakai (mis. halaman QR dengan `pdf-lib`, ±510 KB gzip) tidak dipra-cache bila membuat unduhan pertama melebihi anggaran §5 NFR-P2; ia dicache saat pertama dipakai (cache-first, berhash) |
| FR-P10 | Berkas yang tidak berhash | `/sw.js` dan `/manifest.webmanifest` tidak di-cache lama oleh peramban atau CDN (`Cache-Control: no-cache`), agar pembaruan segera terdeteksi |

### 4.3 Pembaruan versi (Fase 1)
| ID | Kebutuhan | Kriteria penerimaan |
|---|---|---|
| FR-P11 | Deteksi versi baru | Aplikasi memeriksa pembaruan service worker saat dibuka, saat kembali fokus, dan berkala (≤ 1 jam); versi baru siap ditampilkan sebagai spanduk "Ada versi baru — Muat ulang" |
| FR-P12 | Pembaruan atas persetujuan pengguna | Versi baru TIDAK mengambil alih halaman yang sedang dipakai; baru aktif setelah pengguna menekan "Muat ulang" atau menutup semua jendela aplikasi |
| FR-P13 | Tidak ada isian yang hilang | Spanduk tidak memuat ulang otomatis bila ada formulir dengan perubahan belum disimpan (draf task, catatan); tombol "Muat ulang" menyebut hal itu |
| FR-P14 | Keluar (logout) membersihkan data perangkat | Saat keluar: cache query tersimpan (`PERSISTED_CACHE_KEY`) dan (Fase 2) antrean centang dihapus; cache cangkang aplikasi boleh tetap (tidak berisi data pengguna) |

### 4.4 Ketahanan saat server tidak tersedia (Fase 2, menunggu konfirmasi)
| ID | Kebutuhan | Kriteria penerimaan |
|---|---|---|
| FR-P15 | Galat jaringan dipetakan ke `UNAVAILABLE` | `fetch` yang gagal (offline, DNS, timeout) di transport HTTP menghasilkan galat `UNAVAILABLE` "Tidak ada koneksi" (kontrak galat tidak berubah) |
| FR-P16 | Spanduk status | Saat permintaan baca gagal `UNAVAILABLE`: spanduk "Server sedang tidak tersedia — menampilkan data terakhir (hh:mm)" bila ada data tersimpan; spanduk hilang otomatis saat permintaan berikutnya berhasil. Berlaku untuk data yang memang sudah disimpan di perangkat (whitelist `query-persist`); data lain menampilkan galat biasa dengan tombol "Coba lagi" |
| FR-P17 | Antrean centang di perangkat | `handovers.setCheck` yang gagal karena `UNAVAILABLE` ditahan di perangkat (per pemilik akun), ditandai "Menunggu terkirim" pada butir terkait, lalu dikirim berurutan per task saat jaringan/server pulih (`online`, aplikasi kembali fokus, atau permintaan lain berhasil). Hanya centang (idempoten); aksi lain (buat task, simpan item, komentar, ganti nama merk) menampilkan galat dan dapat diulang manual |
| FR-P18 | Penolakan saat dikirim ulang | Entri yang ditolak server (mis. task sudah selesai/dibatalkan, izin dicabut) dibuang dengan pemberitahuan "N perubahan centang tidak dapat dikirim" beserta alasannya; tidak diulang tanpa batas |
| FR-P19 | Kedaluwarsa antrean | Entri yang lebih tua dari 24 jam dibuang dengan pemberitahuan; antrean dibuang saat keluar atau saat pemilik akun berbeda login |

## 5. Kebutuhan Non-Fungsional

| ID | Kebutuhan |
|---|---|
| NFR-P1 | Service worker tidak menambah beban server: cangkang dilayani sebagai berkas statis (`server/src/http/static.ts`) dan service worker hanya membaca dari cache perangkat |
| NFR-P2 | Anggaran pra-cache awal ≤ 5 MB tidak terkompres (diukur dari build, dicek `scripts/verify-dist.ts`); angka final ditetapkan saat implementasi dari hasil build |
| NFR-P3 | Keamanan: service worker hanya melayani origin sendiri; tidak ada respons berotorisasi (API) di Cache Storage; pencabutan akses tetap berlaku ≤ 15 dtk karena tidak ada cache API |
| NFR-P4 | Privasi perangkat: data pengguna di perangkat hanya yang sudah ada sekarang (whitelist `query-persist`, maks. 12 jam, per pemilik token, dibuang saat keluar). Fase 2 menambah antrean centang kecil (id task, kunci butir, nilai, waktu), tanpa isi catatan |
| NFR-P5 | Teks UI berbahasa Indonesia; spanduk dan dialog dapat dipakai di layar ponsel (tanpa gulir horizontal) |
| NFR-P6 | Tidak merusak alur yang ada: login Google (`/auth/login`, `/auth/callback`), sinkron QC Desktop (kini `/api/v1/sync/*`, REST sejak 2026-11-06; sebelumnya `/sync`), dan pengecualian rute server di `server/src/http/static.ts` (`/api`, `/auth`, `/sync`) tidak berubah |
| NFR-P7 | Pembangunan memakai satu dependensi baru (`vite-plugin-pwa`/Workbox) dengan versi dipin yang sudah berumur ≥ 2 minggu; tanpa pustaka state global baru |

## 6. Arsitektur & Keputusan Teknis

### 6.1 Berkas dan build
- `web/public/` (baru): `manifest.webmanifest` (atau dibangkitkan plugin), ikon, dan berkas statis lain. Vite menyalinnya ke `server/dist` bersama build.
- `vite-plugin-pwa` dengan strategi `generateSW` (Workbox), `registerType: 'prompt'` (pembaruan atas persetujuan, FR-P12). `navigateFallback: '/index.html'` dengan `navigateFallbackDenylist: [/^\/api\//, /^\/auth\//, /^\/sync/]` (FR-P8). Rute `/api/*` tidak punya aturan runtime caching (default jaringan).
- Potongan berat (FR-P9): dikecualikan dari pra-cache dengan `globIgnores`, dilayani `CacheFirst` berkunci hash dengan batas jumlah entri.
- Server statis (`server/src/http/static.ts`): `sw.js` dan manifest adalah berkas nyata yang dilayani dengan `Cache-Control: no-cache` (bukan di bawah `/assets/` berhash), sehingga FR-P10 terpenuhi tanpa konfigurasi tambahan; jenis konten manifest `application/manifest+json` diverifikasi saat implementasi (Bun menentukan tipe dari ekstensi; bila salah, ditetapkan eksplisit di `static.ts`).

### 6.2 Frontend
- `web/src/app/pwa/` (baru): pendaftaran service worker, hook status pembaruan, spanduk "Ada versi baru", butir menu "Pasang aplikasi", sinkron `theme-color` dengan `modules/theme` (skrip anti-kedip di `index.html` harus tetap selaras dengan `theme.ts`).
- `index.html`: `<link rel="manifest">`, `<link rel="apple-touch-icon">`, dua `<meta name="theme-color">` bermedia terang/gelap, `apple-mobile-web-app-capable`, `apple-mobile-web-app-title`.
- Logout memanggil pembersih data perangkat (FR-P14).

### 6.3 Fase 2 (menunggu konfirmasi)
- `lib/api/client.ts`: `fetch` gagal → amplop `UNAVAILABLE` (FR-P15).
- Spanduk status global membaca hasil query bergalat `UNAVAILABLE` dan `updatedAt` cache.
- Antrean centang: ekstensi antrean serial per task yang sudah ada (`handover/lib/use-pending-ids.ts`), disimpan di `localStorage` kunci `qc.outbox:<pemilik>`, maks. 200 entri; pengiriman ulang di foreground (tidak mengandalkan Background Sync).

### 6.4 Sesi dan OAuth
Cookie sesi `HttpOnly; Secure; SameSite=Lax` tetap; service worker tidak menyentuh cookie atau navigasi `/auth/*`. Di Android (Chrome/WebAPK) cookie dipakai bersama peramban; di iOS aplikasi terpasang punya penyimpanan terpisah dari Safari sehingga pengguna login sekali di dalam aplikasi terpasang. Alur OAuth di mode `standalone` (terutama iOS) wajib diuji di perangkat nyata (§8).

## 7. Kualitas & Pengujian
- Unit (vitest): hook pembaruan (spanduk muncul/tidak memuat ulang saat ada draf), pemetaan galat jaringan, pembersih data saat logout; Fase 2: antrean centang (urutan per task, kedaluwarsa, penolakan, pemilik berbeda).
- Build (`scripts/verify-dist.ts` diperluas): `sw.js` dan manifest ada; manifest valid dengan semua field FR-P1 dan ikon dengan ukuran benar; daftar pra-cache tidak memuat rute `/api`, `/auth`, `/sync` dan total ≤ anggaran NFR-P2; denylist navigasi memuat `/auth/`.
- Konfigurasi: tes `static.ts` bahwa `sw.js` dan manifest dijawab `no-cache`.
- E2E manual di staging (ditambahkan ke `docs/e2e-checklist.md`): pasang di Android Chrome, iOS Safari, dan desktop; buka cepat di kunjungan kedua; buka rute langsung saat mode pesawat (cangkang tampil, galat jaringan jelas); login Google penuh di mode terpasang (termasuk iOS); deploy versi baru lalu spanduk pembaruan muncul dan "Muat ulang" memuat versi baru; logout membersihkan data perangkat; Fase 2: centang saat server dibuat tidak tersedia lalu pulih.
- Pemeriksaan keterpasangan di DevTools (Application → Manifest/Service Workers) tanpa galat.

## 8. Risiko & Mitigasi
| Risiko | Dampak | Mitigasi |
|---|---|---|
| Cangkang lama dengan kontrak API baru setelah deploy | Galat aneh, fitur rusak | Pembaruan atas persetujuan + pemeriksaan berkala + spanduk (FR-P11–13); perubahan kontrak yang tidak kompatibel mundur disertai penanda versi yang memaksa spanduk |
| Service worker menjawab `/auth/callback` dengan `index.html` | Login gagal total | Denylist `/auth/`, tes build, E2E login penuh di mode terpasang |
| Bug service worker membuat aplikasi macet di versi lama | Pengguna tak bisa memperbarui | `sw.js` `no-cache`; jalur penghapusan: versi berikutnya berisi service worker yang membersihkan cache (`skipWaiting` terkendali + `clientsClaim`); petunjuk cadangan "hapus data situs" |
| iOS: penyimpanan dihapus sistem, tanpa Background Sync, OAuth di mode terpasang | Antrean hilang, login berulang | Antrean hanya untuk centang kecil dengan pemberitahuan; tidak menjanjikan pengiriman di latar belakang; uji login di perangkat iOS nyata sebelum dirilis |
| Data di perangkat bersama (tablet gudang) | Orang lain melihat data pengguna sebelumnya | Hanya whitelist non-sensitif, maks. 12 jam, per pemilik token, dibuang saat keluar; pertanyaan terbuka tentang perangkat bersama (§12) |
| Antrean centang dikirim ke task yang sudah berubah | Centang tak sesuai | Centang idempoten dan tanpa `expectedUpdatedAt` (aturan serah terima); penolakan server diberitahukan (FR-P18) |
| Pra-cache terlalu besar di jaringan seluler | Pemasangan lambat | Anggaran NFR-P2; potongan berat dimuat sesuai kebutuhan (FR-P9) |
| Dependensi baru (Workbox) | Perawatan tambahan | Versi dipin ≥ 2 minggu; konfigurasi kecil; tidak ada kode service worker tulisan tangan di Fase 1 |

## 9. Definition of Done
- [ ] Manifest, ikon (termasuk maskable dan apple-touch-icon), dan `theme-color` terang/gelap terpasang; aplikasi dapat dipasang di Android Chrome, iOS Safari, dan desktop.
- [ ] Service worker menyimpan cangkang aplikasi; kunjungan kedua tidak mengunduh ulang berkas yang tidak berubah.
- [ ] `/api/*`, `/auth/*`, `/sync` tidak pernah dilayani dari cache; login Google penuh berhasil di mode terpasang.
- [ ] Spanduk pembaruan berfungsi dan tidak memuat ulang bila ada draf belum tersimpan.
- [ ] Logout membersihkan data perangkat.
- [ ] `scripts/verify-dist.ts` memeriksa manifest, `sw.js`, anggaran, dan denylist; `bun run check` hijau.
- [ ] E2E staging (Android, iOS, desktop) lulus dan tercatat di `docs/e2e-checklist.md`.
- [ ] `CLAUDE.md` dan `docs/observability.md`/`docs/dev-server.md` diperbarui seperlunya (aturan: jangan menambah API, audit, user, atau isi berkas ke cache service worker).
- [ ] (Fase 2, bila disetujui) galat jaringan → `UNAVAILABLE`, spanduk status, antrean centang dengan pengujian lengkap.

- **Fase 1 dikerjakan lebih dulu dan berdiri sendiri; Fase 2 hanya setelah Anda mengonfirmasi** (cakupannya menyentuh perilaku centang dan penyimpanan data di perangkat).

- Fase 2: hanya **centang** yang diantrekan di perangkat. **Komentar tidak** (mengirim ulang komentar yang responsnya hilang bisa menggandakan komentar; butuh id klien di kontrak, di luar cakupan ini).
- Board dan isi task **tidak disimpan di perangkat** (selaras spek migrasi §7.4); jadi saat server tidak tersedia, board menampilkan galat, bukan data terakhir. Hanya data whitelist yang bisa tampil dari cache.
- Potongan QR (±510 KB gzip) tidak dipra-cache.
