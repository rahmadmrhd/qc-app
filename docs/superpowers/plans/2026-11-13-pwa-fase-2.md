# PWA Fase 2 (Ketahanan saat Server Tidak Tersedia) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Galat jaringan menjadi `UNAVAILABLE`, spanduk "data terakhir" saat server tidak tersedia, dan antrean centang di perangkat yang terkirim otomatis saat server pulih (FR-P15–P19).

**Architecture:** Semua di sisi klien (`web/`); kontrak server dan rute REST tidak berubah. Antrean centang = `localStorage` per pemilik akun (`qc.outbox:<email>`), diisi oleh `useCheckQueue` saat `handovers.setCheck` gagal `UNAVAILABLE`, dikuras oleh penyinkron foreground (`online`, tab terlihat, query berhasil, awal aplikasi). Spanduk status membaca peristiwa `QueryCache`.

**Tech Stack:** React 19, TanStack Query v5, TanStack Router, vitest + Testing Library, sonner (toast), Bun.

**Spec:** `docs/prd/2026-10-26-qc-pwa.md` §4.4 (FR-P15–P19), §6.3, NFR-P4, §7, §8, §9. Fase 1 sudah ada di branch dasar (PR #57).

## Global Constraints

- Fase 2 TIDAK memakai Background Sync, tanpa antrean di server, tanpa kode push; kontrak galat (`ErrorCode`) tidak berubah.
- Hanya `handovers.setCheck` yang diantrekan (komentar, buat task, simpan item, ganti nama merk: tampilkan galat, ulang manual).
- Antrean: kunci `qc.outbox:<email pemilik>`, maks. **200** entri, umur maks. **24 jam**, dibuang saat keluar (`clearSession`), saat pemilik berbeda login, dan penolakan server (FR-P18). Pengiriman berurutan per task, di foreground.
- Board dan isi task TIDAK disimpan di perangkat (keputusan §11); `PERSISTED_KEYS` di `query-persist.ts` tidak bertambah. "Mode baca offline untuk board" TIDAK dikerjakan (belum diputuskan pemilik, §12 butir 4).
- Teks UI bahasa Indonesia santai (memori proyek); serapan asing boleh. Tanpa `<select>` bawaan. Tidak mengubah `shared/`, `server/`, atau `deploy/`.
- Antrean menyimpan `taskId`, `locationId`, `index`, `text` butir (satu baris checklist, dibutuhkan kontrak `SetCheckInput` untuk penjaga "catatan berubah"), `checked`, `at`; tanpa isi catatan lain (NFR-P4).
- Pesan toast/penolakan: "N perubahan centang tidak dapat dikirim" (+ alasan dari `describeError`), "N perubahan centang kedaluwarsa dan dibuang".

## Review Focus

- Penyimpanan penuh/diblokir saat mengantrekan: `enqueue` mengembalikan `false`, butir dikembalikan dan galat biasa tampil (tidak ada centang yang tampak tersimpan padahal tidak).
- `online` + tab terlihat + query berhasil bersamaan: satu pengurasan berjalan (single-flight), tidak ada kirim ganda.
- Keluar/401 di tengah pengurasan: entri yang sudah dihapus tidak ditulis ulang (tidak bangkit kembali).
- Butir yang sama diklik dua kali saat offline: hanya nilai terakhir yang diantrekan (gabung per task+indeks).
- Task sudah Selesai/Dibatalkan, izin dicabut, atau catatan berubah saat dikirim ulang: entri dibuang dengan alasan, tidak diulang.
- Pemilik berbeda login di perangkat yang sama: antrean pemilik lama dibuang diam-diam dan tak pernah dikirim sebagai pemilik baru.
- Reload saat offline: butir tertunda tetap tampak tercentang + "Menunggu terkirim" (overlay dari antrean), bukan kembali kosong.
