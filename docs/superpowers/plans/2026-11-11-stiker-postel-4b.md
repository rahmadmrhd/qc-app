# Stiker Management 4b (Postel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Catatan Postel (daftar nomor sertifikat dengan tanggal habis dan tautan, item pemakai, catatan, lampiran gambar/PDF), satu stiker "Postel" di katalog, peringatan masa berlaku lewat email yang dapat diatur, dan tampilan Postel pada item.

**Architecture:** Tabel baru `postels` + `postel_numbers` + kolom `items.postel_id` (pola `manual_book_design_id` 4a). Jenis sistem `postel` (aturan `group`) berisi satu stiker "Postel" yang dibuat malas; stok memakai jalur stok yang ada tanpa perubahan. Aktif/Lama, kondisi tanggal, dan keputusan kirim email adalah fungsi murni di `shared/postel.ts`. Peringatan = langkah baru penjadwal jam-an (`checkPostelExpiryDigest`) dengan state per nomor dan klaim CAS. Lampiran memakai tabel `files` (pemilik `postel`) lewat rute unggah/unduh baru.

**Tech Stack:** Bun, Hono, MariaDB 11.8 (adaptor `Db`), React + TanStack Router/Query/Form, shadcn, zod, Vitest, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-11-stiker-postel-4b-design.md` (disetujui pemilik 2026-11-11; §3 butir 17 memuat penyesuaian teknis). Peta kode kerja: `.superpowers/sdd/code-map-4b.md` (git-ignored; baca untuk lokasi dan pola). Cabang kerja: `feat/stiker-postel-4b` dari `origin/dev`.

## Global Constraints

- Migrasi `0009_postel_4b.sql`: **expand-only, idempoten** (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE [UNIQUE] INDEX IF NOT EXISTS`), tanpa backfill, tanpa menyunting migrasi lama; tabel baru tanpa FK; `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_nopad_bin`; id `VARCHAR(100)`, waktu `VARCHAR(30)` ISO, `expires_on` `VARCHAR(10)` (`YYYY-MM-DD`), semua pembacaan id di-`.trim()`.
- `shared/` murni (tanpa DOM, `URL`, `fetch`, `atob`), import internal relatif. Batas ukuran literal di `shared/api.ts` dijaga `shared/api.test.ts`.
- Penulisan = pernyataan `DbStatement` dalam `batch()` dengan penjaga CAS (`runGuardedBatch`; galat `isGuardFailure` => `staleError`); jangan baca-lalu-tulis tanpa penjaga. Kolom `key`/`before`/`after` berbacktick; parameter `?`; `SUM/COUNT` dibungkus `Number()`. Bentrok unik lewat NAMA indeks (`postel_numbers_key` => galat `CONFLICT` pada field `number`, pesan generik "Nomor sertifikat sudah dipakai").
- Pesan galat berbahasa Indonesia; galat versi usang lewat `staleError(...)`; pesan konflik item boleh menyebut nomor Aktif Postel lain tetapi tidak merk/BU.

## Review Focus

1. **Item dipasang serentak ke dua catatan Postel** (dan dua simpan serentak atas nomor yang sama): tepat satu berhasil, yang kalah `CONFLICT`; tidak pernah ada item dengan dua penunjuk atau dua catatan dengan nomor sama (Task 4).
2. **Editor tanpa penugasan BU**: `postels.itemOptions` kosong, item tersembunyi tetap terpasang saat penyimpan lain mengganti daftar item, dan jumlahnya (`hiddenItemCount`) tampil tanpa identitas (Task 4).
3. **Berkas lampiran palsu atau tak berhak**: MIME `application/pdf` berisi HTML/PNG, berkas kosong atau > 10 MB, berkas milik modul lain atau unggahan tertunda orang lain via `postelFiles.get`, serta lampiran ke-11 (Task 5).
4. **Batas hari dan zona waktu**: `expires_on` = hari ini masih Berlaku (sisa 0), tengah malam WIB, 29 Februari, tanggal tak nyata, dan ambang diubah setelah email terkirim tidak mengirim ulang maupun menahan peringatan (Task 1, 8).
5. **Email dobel atau hilang**: dua penjadwal serentak mengirim satu surel, kegagalan kirim memulihkan klaim, nomor Lama tak pernah diperingatkan, tanggal diperpanjang mereset state, dan isi surel tanpa nama item atau jumlah item (Task 8).
6. **Perluasan aturan jenis sistem**: stiker Postel dapat diaktifkan kembali dan gambarnya diganti sementara Manual Book tetap terkunci; filter instruksi dan `items.get` sepakat untuk Postel (Task 3, 7).
