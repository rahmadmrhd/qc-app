## Aturan bersama semua paket
- Hanya menyunting berkas yang DIMILIKI paket Anda (daftar di bawah). Berkas milik paket lain: jangan disentuh; bila perlu perubahan di sana, catat di laporan sebagai kekhawatiran. Typecheck/tes web dapat menampilkan galat dari pekerjaan paket lain yang sedang berjalan serentak (terutama sekitar `serial/act-*`); abaikan galat di luar berkas Anda.
- Komit dengan PATHSPEC: `git add <berkas>` lalu `git commit -m "..." -- <berkas yang sama>` (jangan `git add -A`, jangan `git commit -a`). Bila `index.lock` bentrok dengan agen lain, tunggu beberapa detik dan ulangi. Akhiri pesan komit dengan `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Pesan komit gaya `tipe(area): ringkasan` berbahasa Indonesia. TIDAK push. TIDAK membuat PR.
- JANGAN menjalankan atau menghentikan server dev, terowongan DB, atau proses di port 3000; JANGAN memakai browser pane (verifikasi visual dilakukan pemilik sesi). Tes server butuh terowongan DB yang sudah hidup (`127.0.0.1:33063`): jalankan SATU berkas per perintah (`QC_TEST_SHARDS=1 bun run --cwd server test <jalur>`), jangan tes server penuh; bila muncul `Too many connections`, tunggu dan ulangi sendiri, jangan menyimpulkan itu regresi.
- Jangan men-spawn subagent. Ikuti aturan frontend di `CLAUDE.md` (Link/ComboBox, `FileDialog`, kit CRUD, dialog, navigasi ponsel, token warna `-text`, tanpa `<select>`, jangan memasang `container-type` pada `<main>`/`FormPage`).
- Tiap perubahan perilaku: tes regresi yang membuktikannya; jangan melemahkan tes lama (mengubah ekspektasi hanya bila spek mengubah perilakunya, dengan alasan di laporan).
- Gerbang sebelum melapor: `bun run --cwd web test <folder/berkas yang disentuh>` (beberapa tes timeout saat beban penuh: ulangi sendiri), `bun run typecheck` (akar), `bunx biome check <berkas>`, penjaga `bun test scripts/<yang relevan>` (page-frame, no-native-select, mobile-navigation-guard, no-raw-palette, no-legacy-variants), `bun run changelog validate server|desktop` bila menyentuh fragmen. Berkas CRLF/LF: pertahankan akhir baris asli berkas.
- Laporan penuh ke `.superpowers/sdd/2026-11-22-revisi-lanjutan-2/<paket>-report.md`. Yang dikembalikan ke pemanggil HANYA: status (DONE / DONE_WITH_CONCERNS / BLOCKED), daftar komit, satu baris ringkasan tes, kekhawatiran.

### W1 Tempel stiker: server, shared, dialog satu serial (R1)
Catatan riset: `research-serial.md` bagian 1 (rancangan teknis Opsi A, batch, tes terdampak).
**Milik:** `shared/serials.ts`, `shared/serial-flow.ts` (+ tes), `shared/contract.ts`, `shared/api.ts`, `shared/api-contract.snapshot.json`, `shared/api.test.ts`, `shared/serials.test.ts`, `server/src/modules/serial/**` (act, validate, routes, `stickers-batch.ts` baru, tes), `server/changelog.d/20261122-revisi-lanjutan-2.md` (baru), `desktop/changelog.d/20261122-revisi-lanjutan-2.md` (baru; perubahan `shared/` memicu cek fragmen desktop; isi satu atau dua baris `change(...)` yang jujur), dan di web HANYA: `web/src/modules/serial/components/{act-buttons,act-dialog,act-fields}.tsx`, `web/src/modules/serial/lib/labels.ts` (+ tesnya), `web/src/modules/serial/queries.ts` (hook batch).
**Antarmuka yang dihasilkan (dipakai W5):**
- `SerialAction` memuat `'apply_stickers'`; `SERIAL_EVENT_TYPES` memuat `'stickers_applied'`; label web `ACTION_LABEL.apply_stickers = 'Tempel stiker'`, `EVENT_LABEL.stickers_applied = 'Stiker ditempel'`; kelompok riwayat "Perubahan data".
- `SerialActInput` varian `{ action: 'apply_stickers'; stickerIds: string[] }` (minimal 1, maks. `SERIAL_LIMITS.picksMax`).
- `serials.applyStickersBatch` (`POST /serials/batch/stickers`, `serial: edit`, didaftarkan SEBELUM `/serials/{id}`): input `{ clientId: string (UUID huruf kecil); occurredOn: string; message: string; rows: { id: string; stickerIds: string[] }[] }` (1..100 baris, id unik), output `{ ids: string[] }` atau `BatchResult` bila lebih cocok dengan `shared/batch.ts`; atomik lewat `runRecordBatch`; perencana per baris dibagi dengan `applyAct` (ekstrak `planApplyStickers`); idempoten lewat `serial_events.client_id = <clientId>:<serialId>`; galat menyebut nomor serial; hak per baris seperti `applyAct`; serial terhapus = `NOT_FOUND`.
- Web: `ActKind` `'stickers'` (label "Tempel stiker", ikon `Sticker`), `KIND_OF.apply_stickers`, `actButtonSpecs` memuatnya; `ActDialog kind="stickers"` (daftar centang `RecheckStickerList` dengan prop teks agar tak menyebut "ulang", tanggal, catatan opsional, wajib minimal satu centang); hook `useApplyStickersBatch` di `queries.ts` (menandai basi `serialKeys.list`, `one`, `history`, stok stiker, audit).
**Tes:** `serial-flow.test` (baris baru, matriks negatif, `availableActions` urutan), `serials.test`, `labels.test`, `act-flow.test` server (aksi, stok -1, stiker nonaktif ditolak, stiker tak berlaku ditolak, status/custody salah, CAS), tes batch (atomik, idempoten kirim ulang tak memotong stok dua kali, satu baris gagal membatalkan semua, hak per baris, konkurensi `Promise.all`), `api.test` + `bun run api:snapshot` (196 -> 197), OpenAPI.
