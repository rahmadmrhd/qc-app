# QC App — panduan untuk agen

Aplikasi Quality Control: frontend React + TanStack; backend Bun + Hono + MariaDB di `server/` (`Dockerfile` dan `deploy/compose.yml` ada sejak T26; CI/CD nyata berjalan sejak 2026-11-07 (BuildKit, GHCR, deploy SSH, rollback otomatis, `pull_request_target`); production `qc.rhd.my.id` live sejak cutover 2026-11-07; Google Drive/Sheets diakses LANGSUNG lewat service account sejak T30a). Aplikasi Google Apps Script + Google Sheets lama dan jembatannya sudah dipensiunkan (T35, 2026-11-07): kodenya hanya ada di tag `gas-legacy`; halaman `/exec` lama dialihkan ke `qc.rhd.my.id` lewat proyek `clasp` lokal pemilik di luar repo (spek §19 butir 14).
PRD: `docs/prd/`. Rencana implementasi: `docs/superpowers/plans/`.

## Perintah
- `bun run dev` — server Bun (`server/`, :8788) + Vite (:3000) yang mem-proxy `/api`, `/auth`, `/sync` ke server (`SERVER_DEV_URL`). Prasyarat sekali: salin `server/.env.example` menjadi `server/.env`; jalankan `bun run db:tunnel` di terminal lain dan biarkan terbuka (SSH ke MariaDB dev di VPS, `127.0.0.1:33063`; `bun run dev` memeriksanya dan memberi petunjuk bila mati); lalu `bun run db:seed` (migrasi + data contoh, hanya ke skema `qc_dev`). Login lewat "Masuk sebagai pengguna dev" (`DEV_LOGIN_EMAIL`). Drive/Sheets lokal hanya bila `GOOGLE_SA_KEY_FILE` + `GOOGLE_ROOT_FOLDER_ID` diisi di `server/.env` (`docs/setup-google.md`); tanpa itu = `UNAVAILABLE`. Rincian: `docs/dev-server.md`.
- `bun run db:tunnel` — terowongan SSH ke MariaDB dev/tes di VPS; wajib hidup untuk `dev`, `db:seed`, dan tes server.
- `bun run check` — typecheck + Biome + semua test. Butuh tunnel hidup (tanpa itu GAGAL, bukan dilewati). Tes server (`bun run --cwd server test`) dibagi ke 3 proses `bun test` paralel (bawaan; `QC_TEST_SHARDS`, maks. 4 karena `max_connections` VPS 40), tiap berkas memakai skema MariaDB sementaranya sendiri; satu berkas/folder: `bun run --cwd server test src/modules/brand`. Wajib hijau sebelum commit.
- `bun run build` — build web (Vite, potongan JS/CSS dengan lazy load per rute) ke `server/dist` (berkas statis yang dilayani server Bun dengan fallback SPA), lalu `verify-dist`: `index.html` ada, tanpa kode mock, dan tiap potongan JS ≤ 600 KB gzip.
- Bun terpasang di `~/.bun/bin`; bila `bun` tidak ditemukan di shell, tambahkan ke PATH.

## Aturan server (Bun + MariaDB)
- Kabel REST (`/api/v1`; satu-satunya kabel aplikasi web, `/api/rpc` dan `/api/boot` sudah dihapus): SATU tabel `API_ROUTES` di `shared/api.ts` (verba, jalur, query, `ifMatch`, `etag`, `create`) dipakai klien FE (`web/src/lib/api`, `api(id, input)`), kernel server (`http/rest.ts`: urutan: `authorize` (sesi + izin global, `core/router.ts`) -> baca badan -> `fromRequestParts` (merakit input datar) -> `execute` (validasi, izin berlokasi, handler; `runRoute` = `authorize` + `execute`), jadi validator/handler modul tak berubah), dan OpenAPI (`GET /api/openapi.json`, butuh sesi). Semua id kontrak (`ApiId`) terdaftar (`registerRest(app, routes)` tanpa himpunan; `shared/api.test.ts` menjaga tabel dan kontrak sejalan). Data awal klien = `GET /api/v1/me` (`auth.me`). Amplop `{ ok, data | error }` milik aplikasi Apps Script lama sudah dihapus (T35); nama "RPC" (`shared/rpc.ts`, `RpcMethod`, `RpcInput`, `RpcOutput`, `RpcContract`, `restRpc`) diganti `shared/contract.ts`, `ApiId`, `ApiInput`, `ApiOutput`, `ApiContract`, `restCall` pada 2026-11-08 (keputusan pemilik: kabelnya sudah REST, namanya jangan menyesatkan); `scripts/no-legacy-rpc.test.ts` menjaga web/server/shared bersih dari sisa kabel lama. Galat = `application/problem+json` (`http/problem.ts`; `code` tetap kode kontrak); galat versi usang WAJIB dilempar lewat `staleError(message)` (bukan `appError('CONFLICT', ...)`) agar menjadi 412 bila rute berETag dan permintaan membawa `If-Match`. Rute biner (`binary: 'request' | 'multipart' | 'response'`) memakai badan mentah/multipart/unduhan dengan batas ukuran per rute di tabel (413 tanpa membaca seluruh badan). Urutan di kernel: `authorize` (sesi HMAC, akun aktif, izin global) SEBELUM badan apa pun dibaca, lalu baca badan, `fromRequestParts`, dan `execute` (validasi, izin berlokasi, handler); `runRoute` = `authorize` + `execute` (dipakai juga tes). Respons JSON `Cache-Control: no-store` dan klien memakai `cache: 'no-store'` (ETag `updatedAt` bukan validator isi: komentar/ganti nama merk tak menaikkannya, jadi cache HTTP dapat menyajikan 304 basi); ETag tetap dikirim untuk `If-Match` dan klien yang sendiri mengirim `If-None-Match`. Unduhan biner memakai kebijakan cache tabelnya.
- Adaptor `Db` (`server/src/core/db.ts`) berbentuk `prepare/bind/run` di atas mysql2: `prepare(sql).bind(...).run/all/first`, `batch([...])` = SATU transaksi, `transaction(fn)` untuk logika dengan baca-lalu-tulis di dalam transaksi (deadlock mengulang `fn` sekali, jadi `fn` tanpa efek luar basis data), `exec()` multi-pernyataan hanya untuk SQL tepercaya (migrator, harness). Parameter selalu `?` berurutan (bukan `?1`) dan nilai SELALU di-bind. Kolom `key`/`before`/`after` wajib berbacktick. `SUM`/`COUNT` dapat kembali sebagai string/DECIMAL: bungkus `Number()`. Galat driver diterjemahkan menjadi `DbError{errno, kind: duplicate|out_of_range|deadlock|unavailable|other, key}`; `unavailable` (MariaDB tak terjangkau) dipetakan ke `UNAVAILABLE` untuk klien.
- Penjaga CAS (`core/cas.ts`): syarat tulis digabung ke `UPDATE`/`INSERT` (`CAS_UPDATED_AT_SET`, `CAS_VERSION_BUMP_SET`), dan syarat yang gagal mengeluarkan `CAS_FAIL_SQL` (`-9223372036854775807 - 2`, di luar rentang BIGINT: galat 1690, dikenali `isGuardFailure`) sehingga seluruh `batch()` dibatalkan; bukan `SELECT` penjaga terpisah. MariaDB tidak punya `UPDATE ... RETURNING`: nilai baru dibaca lewat `SELECT` di akhir batch yang sama (mis. pembacaan baris merk di akhir batch `setBrandStatusOnce`). Bentrok kunci unik dipetakan lewat NAMA INDEKS baseline (`mapDuplicateError`, peta konflik per modul, mis. `items_key`, `handovers_number`): jangan mengganti nama indeks tanpa memperbarui peta itu.
- Isolasi: `innodb_snapshot_isolation` dimatikan per sesi (MariaDB ≥ 11.6.2 menyalakannya dan melempar galat 1020 pada penghitung bersama seperti `counters`). Penulisan yang bergantung pada apa yang baru dibaca dijaga SALAH SATU dari: CAS di dalam `batch()` (syarat digabung ke `UPDATE`/`INSERT`, gagal = `CAS_FAIL_SQL`, dibungkus `runCas` yang memuat ulang dan mengulang; nomor berurutan `ST-…` memakai penghitung CAS `INSERT … ON DUPLICATE KEY UPDATE`, BUKAN `FOR UPDATE`) atau kunci baris `SELECT ... FOR UPDATE` (ganti nama merk dan penjaga merk pada penulisan item, `brandKeyGuardStmt`; kunci baris `handovers` di operasi tertentu). Jangan baca lalu tulis tanpa salah satunya. Tes konkurensi memakai `Promise.all` atas permintaan nyata; jangan dilemahkan.
- Kolasi server dan sesi `utf8mb4_nopad_bin`: perbandingan membedakan huruf besar/kecil dan spasi ekor (setara BINARY); kecocokan tak-peka-huruf lewat kolom `key` ternormalisasi (`normalizeKey`/`itemKey` di `shared/`), bukan kolasi. `CHAR_LENGTH` menghitung karakter (emoji = 1), `LENGTH` menghitung byte; pembagian bulat dengan `DIV`; `LOCATE` menggantikan `instr`.
- Migrasi: `server/migrations/NNNN_nama.sql` (urut nama, dicatat di `schema_migrations`). DDL MariaDB TIDAK transaksional (implicit commit): tulis idempoten (`IF NOT EXISTS`) dan hindari DDL non-idempoten; mengubah skema = migrasi baru, bukan menyunting yang sudah diterapkan. Hash migrasi memperbarui templat tes otomatis. Perubahan `deploy/compose.yml` dan `deploy/.env.example` tidak dibawa CI, jadi nilainya harus diisi manual di `.env` VPS SEBELUM push yang men-deploy. Sisi klien (rencana `docs/superpowers/plans/2026-11-13-push-klien.md`): handler `push` dan `notificationclick` di `web/public/push-sw.js` (skrip klasik, diimpor service worker Workbox lewat `workbox.importScripts` di `pwa-config.ts`, tidak dipra-cache; selalu menampilkan notifikasi, tautan hanya path same-origin yang divalidasi `safeUrl`, selain itu `/`); modul `web/src/modules/push/` (`lib/` support, storage penanda per email, subscribe, sync; `queries.ts`; `components/`). `push.config` membawa `userEnabled` (preferensi pemanggil, bawaan aktif). `PushOnboarding` (dipasang di `AppShell`): izin `granted` = berlangganan diam-diam sekali per sesi tab (akun kedua di perangkat sama ikut tertaut); izin `default` pada PWA terpasang dan belum pernah ditanya = dialog pra-izin lalu `Notification.requestPermission()` SEKALI atas klik pengguna (Nanti = tak ditanya lagi, tetap bisa dari menu profil "Notifikasi push"); izin `denied` = tidak pernah diminta ulang, banner pengingat paling sering sekali per 7 hari (`BANNER_INTERVAL_MS`) dengan langkah per platform; izin peramban dilaporkan ke server tiap berubah HANYA dari PWA terpasang dan tidak pernah `default` (server menyimpan satu nilai per pengguna; tab/perangkat lain tak boleh menimpanya). `syncThisDevice` berbagi satu alur pada satu waktu dan dicoba ulang saat jendela fokus bila gagal. Saklar push dan status perangkat di `PushSettingsDialog` (menu profil); halaman admin `/access/push` "Status Push" (`access: view`, lima status tanpa pengenal perangkat). Logout tidak menyentuh langganan. Uji ujung ke ujung di perangkat nyata butuh VAPID terisi di staging (E2E N18).


## Aturan `shared/` dan cache frontend
- `shared/` dipakai server dan web: murni (tanpa API runtime/DOM: `URL`, `fetch`, `atob`, dll.), import internal relatif. Batas ukuran di `shared/api.ts` sengaja literal; tes (`api.test.ts`) menjaganya sama dengan konstanta sumbernya.
- Cache data (frontend): mutasi QR dan item memasang hasil server langsung ke cache (`web/src/lib/query-cache.ts`: `upsertInList`, `removeFromList`, `markStale`) dan TIDAK menunggu muat ulang (sebelumnya simpan + muat ulang daftar berurutan); `app/prefetch.ts` mem-prefetch daftar yang boleh dibaca sekali saat beranda diam (batch); `app/query-persist.ts` menyimpan query whitelist (me, items, brands, qrcodes) di localStorage per pemilik token, dipulihkan sebelum router dibuat (tampil instan lalu dimuat ulang), dibuang saat keluar. Jangan menambah Log Audit, user, atau isi berkas ke whitelist.

## Aturan frontend
- **Field relasi wajib `LinkField`/`LinkMultiField`** (keputusan pemilik 2026-11-10; spek BU keputusan 24): SETIAP field form yang nilainya merujuk record model/tabel lain (merk, BU, jenis stiker, preset QR, role, lokasi pada penugasan user, dst.) memakai `LinkField` (satu pilihan) atau `LinkMultiField` (banyak pilihan) dari `web/src/components/link-field.tsx`, BUKAN `Select`, daftar checkbox, atau input teks bebas; berlaku juga untuk filter di halaman daftar yang nilainya record model lain (keputusan 2026-11-11, spek BU butir 25). Saran dari daftar yang sudah dimuat disaring lokal; daftar besar memakai `onSearchChange` dan `hasMore`. Baris "Tambah {label}" (`onCreate`) hanya bila sudah ada dialog tambah dan user berhak; tautan "Buka" (`openHref`) hanya bila ada halaman lihat record dan user berhak (model tanpa halaman lihat, mis. jenis stiker, preset QR, lokasi, role, tidak punya Buka dan tidak membuat rute baru). Izin Tambah/Buka dipusatkan di `web/src/lib/link-access.ts` (`businessUnitLinkAccess`, `brandLinkAccess`, `stickerTypeLinkAccess`, `stickerLinkAccess`, `itemLinkAccess`, `manualBookLinkAccess`, `itemFormLinkAccess`); tambah fungsi baru di sana, jangan menghitung izin di komponen. Dialog "Tambah" dirender DI LUAR `<form>` induk (React meneruskan event submit lewat portal) dan record baru langsung terpilih tanpa menunggu muat ulang. Pengecualian (bukan relasi model atau bukan field form): enum/daftar tetap (status, aturan, cara input, urutan, aksi audit, mode filter) memakai `Select`/`MultiSelect` (`web/src/components/select.tsx`; BUKAN `<select>` bawaan: `NativeSelect` sudah dihapus), pemilih visual (`LogoPicker`, `ImagePicker`), dan `CustomerCombobox` (teks bebas; customer dibuat otomatis saat task disimpan, FC2). `LocationField` (`web/src/modules/location/location-field.tsx`, form tulis modul berlokasi) TIDAK dikecualikan: isinya `LinkField` (tanpa Tambah/Buka). Tes: helper `pickLink`/`linkOptionNames` (alias `pickSelect`/`selectOptionNames` untuk `Select`) di `web/src/test/link-field.ts`. `LinkField`, `LinkMultiField`, `Select`, dan `MultiSelect` berbagi satu inti `web/src/components/combobox.tsx` (`ComboboxBase`: portal daftar, pencarian lokal `localFilter` dengan sorotan `highlight`, `hideLabel` untuk filter tanpa label tampak, `className` pembungkus); daftar record yang seluruhnya sudah dimuat memakai `LinkField` + `localFilter`. Form baru wajib mengikuti aturan ini (mis. instruksi stiker per item, tahap 3b-2).
- **Jangan pernah memakai elemen `<select>` HTML bawaan** (keputusan pemilik 2026-11-11): untuk pilihan apa pun, enum/daftar tetap maupun record model lain, pakai `Select`/`MultiSelect` (`web/src/components/select.tsx`) atau `LinkField`/`LinkMultiField` (field relasi). Jangan membuat pembungkus `<select>` baru, `NativeSelect`, atau `<option>`/`<optgroup>` di kode web; komponen shadcn `ui/select` (Radix Select) juga tidak dipakai. Daftar pilihan harus lewat inti `web/src/components/combobox.tsx` agar tampilan, keyboard, dan perilaku portal di dalam dialog seragam. Tes memilih opsi lewat `pickSelect`/`pickLink`, bukan `userEvent.selectOptions`. Dijaga `scripts/no-native-select.test.ts` (gagal bila `web/src` memuat `<select>`, `<option>`, `<optgroup>`, `NativeSelect`, atau `ui/select`; komentar diabaikan).
- **Dialog dan alert dialog** (`ui/dialog.tsx`, `ui/alert-dialog.tsx`, `form-dialog.tsx`; keputusan pemilik 2026-11-11): header dan footer SELALU tetap terlihat dan hanya badan yang di-scroll. `DialogContent`/`AlertDialogContent` adalah cangkang tinggi-terbatas (`max-h-[calc(100dvh-2rem)]`, `overflow-hidden`) berisi satu penggulir (`data-slot="dialog-scroll"`/`"alert-dialog-scroll"`) yang membungkus SEMUA anak; `DialogHeader`/`DialogFooter` (dan versi AlertDialog) menempel (`sticky`, offset `-top-4`/`-bottom-4` mengimbangi `-mt-4`/`-mb-4`: sticky mengukur kotak margin). Pemakai cukup menaruh Header, isi, Footer apa adanya (footer boleh di dalam `<form>`); JANGAN menambah `max-h-*`/`overflow-y-auto` pada `*DialogContent` atau pembungkus badan sendiri. Tombol tutup (X) berada di luar penggulir (`absolute`, `z-20`). Dialog yang butuh area dalam yang menyusut (file dialog, pratinjau lembar) memakai `min-h-0 flex-1 overflow-*` pada anaknya seperti biasa.
- Daftar saran `LinkField`/`LinkMultiField` dirender di `document.body` lewat portal (`position: fixed`, letak dari `placeList` mengikuti kotak input, membuka ke atas bila ruang bawah sempit) agar tidak terpotong penggulir dialog. Karena di luar dialog Radix, daftar memakai `pointerEvents: 'auto'` dan menahan `pointerdown`/`wheel`/`touchmove` (dialog menutup/mengunci gulir untuk peristiwa di luar kontennya). Tes harus mencari opsi lewat `screen`, bukan `within(dialog)` (helper `pickLink`/`linkOptionNames` sudah begitu).
- Komponen UI dari shadcn (`web/src/components/ui`, dikecualikan dari lint). Tambah lewat `bunx --bun shadcn@latest add <komponen>` dari folder `web/`. shadcn 4 memakai paket `cn` (shadcn-ui/cn), bukan `clsx`+`tailwind-merge`.
- Server state: TanStack Query; form: TanStack Form + zod; filter/halaman: search params Router. Tanpa library state global.
- Tema: `modules/theme` (kelas `dark` di `<html>`); skrip anti-kedip di `web/index.html` harus selaras dengan `theme.ts`.
- Service worker tidak boleh men-cache `/api`, `/auth`, `/sync`, isi berkas, Log Audit, atau data pengguna; perubahan `SERVER_PREFIXES` di `server/src/http/static.ts` wajib diikuti `SERVER_PATH_DENYLIST` (dijaga `scripts/pwa-server-paths.test.ts`).
- Jangan menaruh kode mock di build produksi (dicek `scripts/verify-dist.ts`).

## Menambah rute REST
1. Tambah id di `ApiContract` (`shared/contract.ts`, tipe input/output) dan entri di `API_ROUTES` (`shared/api.ts`: verba, jalur, query, `ifMatch`/`etag`/`create` bila perlu).
2. Validator + handler di `server/src/modules/<modul>/`, daftarkan di `<modul>/routes.ts` dengan `permission` yang tepat; `getRoutes()` bertipe `RouteTable` sehingga typecheck gagal bila id belum terdaftar.
3. FE: `queryOptions`/mutation di `web/src/modules/<modul>/queries.ts` memakai `api(id, input)` (`web/src/lib/api`).
4. Tes REST di `<modul>/rest.test.ts` lewat `restClient`/`restCall` (`server/test-support`); OpenAPI (`GET /api/openapi.json`) otomatis memuat id baru.
5. Modul berlokasi: tandai `scope: 'location'` pada izin rute dan pakai `ctx.locationIds` (lihat `docs/adding-a-module.md`). Izin "salah satu dari": pakai `anyOf` (lihat `docs/adding-a-module.md`). Modul ber-BU (daftar `BU_MODULES` di `shared/business-units.ts`; saat ini `item`, `serial`, `serialservice`) tidak memakai `scope: 'location'`; resepnya ada di `docs/adding-a-module.md`, bagian "Modul ber-BU".

Resep modul baru: `docs/adding-a-module.md`.
