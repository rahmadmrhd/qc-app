# QC App — panduan untuk agen

Aplikasi Quality Control: frontend React + TanStack; backend Bun + Hono + MariaDB di `server/` (hasil port dari Cloudflare Worker; kabel REST dan Docker belum ada) dan aplikasi Google Apps Script (GAS) + Google Sheets lama di `gas/` yang masih ada sampai cutover.
PRD: `docs/prd/`. Rencana implementasi: `docs/superpowers/plans/`.

## Perintah
- `bun run dev` — server Bun (`server/`, :8788) + Vite (:3000) yang mem-proxy `/api`, `/auth`, `/sync` ke server (`SERVER_DEV_URL`). Prasyarat sekali: salin `server/.env.example` menjadi `server/.env`; jalankan `bun run db:tunnel` di terminal lain dan biarkan terbuka (SSH ke MariaDB dev di VPS, `127.0.0.1:33063`; `bun run dev` memeriksanya dan memberi petunjuk bila mati); lalu `bun run db:seed` (migrasi + data contoh, hanya ke skema `qc_dev`). Login lewat "Masuk sebagai pengguna dev" (`DEV_LOGIN_EMAIL`). Jembatan Google tidak tersedia lokal. Rincian: `docs/dev-server.md`.
- `bun run db:tunnel` — terowongan SSH ke MariaDB dev/tes di VPS; wajib hidup untuk `dev`, `db:seed`, dan tes server.
- `bun run check` — typecheck + Biome + semua test. Butuh tunnel hidup (tanpa itu GAGAL, bukan dilewati). Tes server (`bun run --cwd server test`) dibagi ke 3 proses `bun test` paralel (bawaan; `QC_TEST_SHARDS`, maks. 4 karena `max_connections` VPS 40), tiap berkas memakai skema MariaDB sementaranya sendiri; satu berkas/folder: `bun run --cwd server test src/modules/sync`. Wajib hijau sebelum commit.
- `bun run build` — build web (Vite, potongan JS/CSS dengan lazy load per rute) ke `server/dist` (berkas statis yang dilayani server Bun dengan fallback SPA), lalu `verify-dist`: `index.html` ada, tanpa kode mock, dan tiap potongan JS ≤ 600 KB gzip. Aplikasi Apps Script lama: `bun run build:gas` (`gas/dist` + `verify-gas-dist`); jembatan: `bun run build:bridge`.
- `bun run push` / `bun run deploy` — push ke Apps Script / perbarui deployment tetap (`gas/deployment.json`).
- Bun terpasang di `~/.bun/bin`; bila `bun` tidak ditemukan di shell, tambahkan ke PATH.

## Struktur
- `shared/` — kontrak FE↔GAS (`rpc.ts`) dan model permission. Murni, tanpa API GAS/DOM, import internal relatif.
- `gas/src/` — backend. `main.ts` (doGet, api, setup), `routes.ts`, `core/`, `modules/<modul>/{repo,context,validate,service,routes}.ts`.
- `gas/test-support/` — memory platform & fixture (dipakai test dan mock FE; tidak di-build).
- `server/` — backend baru: Bun + Hono + MariaDB 11.8 (kabel: REST `/api/v1` untuk seluruh aplikasi web dan `/sync` lama untuk QC Desktop sampai T25). Tiap modul GAS punya padanan di `server/src/modules/<modul>/` (repo, service, routes, validate). `src/app.ts` (`createApp(routes)`; aplikasi Hono: `/api/ping`, `/api/v1/*`, `/api/openapi.json`, `/auth/*`, `/sync`, lalu berkas statis + fallback SPA), `src/server.ts` (`createServer(config)`: `Env` dari konfigurasi + runner job + penjadwal), `src/main.ts` (`Bun.serve`, shutdown rapi pada SIGTERM/SIGINT), `src/config.ts` (`loadConfig`; variabel di `server/.env.example`), `src/http/` (`proxy.ts` `clientIp`, `security.ts`, `static.ts`, `rest.ts` kernel REST, `problem.ts`, `openapi.ts`), `src/core/` (`db`, `cas`, `router`, `session`, `migrate`, `file-cache`, jembatan Google), `src/jobs/` (runner job internal + penjadwal), `migrations/` (skema baseline), `test-support/` (harness tes MariaDB, jembatan palsu), `scripts/` (`test.ts` runner terpecah, `seed-dev.ts`).
- `web/src/` — `modules/<modul>/` (queries, schemas, components), `routes/` (tipis), `app/` (shell, router, boot), `lib/api/` (klien REST `api()`, `ApiError`, `describeError`), `modules/theme/` (terang/gelap/sistem).

## Aturan server (Bun + MariaDB)
- Kabel REST (`/api/v1`; satu-satunya kabel aplikasi web, `/api/rpc` dan `/api/boot` sudah dihapus): SATU tabel `API_ROUTES` di `shared/api.ts` (verba, jalur, query, `ifMatch`, `etag`, `create`) dipakai klien FE (`web/src/lib/api`, `api(id, input)`), kernel server (`http/rest.ts`: merakit input datar lewat `fromRequestParts` lalu `runRoute` di `core/router.ts`, jadi validator/handler modul tak berubah), dan OpenAPI (`GET /api/openapi.json`, butuh sesi). Semua id kontrak Worker terdaftar (`registerRest(app, routes)` tanpa himpunan; `shared/api.test.ts` menjaga tabel dan kontrak sejalan). Data awal klien = `GET /api/v1/me` (`auth.me`). Amplop RPC `{ ok, data | error }` hanya tersisa untuk aplikasi GAS (`shared/gas-legacy.ts`, dihapus bersama `gas/` di T35) dan `/sync`; `scripts/no-legacy-rpc.test.ts` menjaga web/server/shared bersih dari sisa kabel lama. Galat = `application/problem+json` (`http/problem.ts`; `code` tetap kode kontrak); galat versi usang WAJIB dilempar lewat `staleError(message)` (bukan `appError('CONFLICT', ...)`) agar menjadi 412 bila rute berETag dan permintaan membawa `If-Match`. Rute biner (`binary: 'request' | 'multipart' | 'response'`) memakai badan mentah/multipart/unduhan dengan batas ukuran per rute di tabel (413 tanpa membaca seluruh badan). Urutan di kernel: `authorize` (sesi HMAC, akun aktif, izin global) SEBELUM badan apa pun dibaca, lalu baca badan, `fromRequestParts`, dan `execute` (validasi, izin berlokasi, handler); `runRoute` = `authorize` + `execute` (dipakai juga tes). Respons JSON `Cache-Control: no-store` dan klien memakai `cache: 'no-store'` (ETag `updatedAt` bukan validator isi: komentar/ganti nama merk tak menaikkannya, jadi cache HTTP dapat menyajikan 304 basi); ETag tetap dikirim untuk `If-Match` dan klien yang sendiri mengirim `If-None-Match`. Unduhan biner memakai kebijakan cache tabelnya.
- Adaptor `Db` (`server/src/core/db.ts`) berbentuk D1 di atas mysql2: `prepare(sql).bind(...).run/all/first`, `batch([...])` = SATU transaksi, `transaction(fn)` untuk logika dengan baca-lalu-tulis di dalam transaksi (deadlock mengulang `fn` sekali, jadi `fn` tanpa efek luar basis data), `exec()` multi-pernyataan hanya untuk SQL tepercaya (migrator, harness). Parameter selalu `?` berurutan (bukan `?1`) dan nilai SELALU di-bind. Kolom `key`/`before`/`after` wajib berbacktick. `SUM`/`COUNT` dapat kembali sebagai string/DECIMAL: bungkus `Number()`. Galat driver diterjemahkan menjadi `DbError{errno, kind: duplicate|out_of_range|deadlock|unavailable|other, key}`; `unavailable` (MariaDB tak terjangkau) dipetakan ke `UNAVAILABLE` untuk klien.
- Penjaga CAS (`core/cas.ts`): syarat tulis digabung ke `UPDATE`/`INSERT` (`CAS_UPDATED_AT_SET`, `CAS_VERSION_BUMP_SET`), dan syarat yang gagal mengeluarkan `CAS_FAIL_SQL` (`-9223372036854775807 - 2`, di luar rentang BIGINT: galat 1690, dikenali `isGuardFailure`) sehingga seluruh `batch()` dibatalkan; bukan `SELECT` penjaga terpisah. MariaDB tidak punya `UPDATE ... RETURNING`: nilai baru dibaca lewat `SELECT` di akhir batch yang sama (mis. `readSyncRevStmt`). Bentrok kunci unik dipetakan lewat NAMA INDEKS baseline (`mapDuplicateError`, peta konflik per modul, mis. `items_key`, `handovers_number`): jangan mengganti nama indeks tanpa memperbarui peta itu.
- Isolasi: `innodb_snapshot_isolation` dimatikan per sesi (MariaDB ≥ 11.6.2 menyalakannya dan melempar galat 1020 pada penghitung bersama seperti `sync_state`/`counters`). Penulisan yang bergantung pada apa yang baru dibaca dijaga SALAH SATU dari: CAS di dalam `batch()` (syarat digabung ke `UPDATE`/`INSERT`, gagal = `CAS_FAIL_SQL`, dibungkus `runCas` yang memuat ulang dan mengulang; nomor berurutan `ST-…` memakai penghitung CAS `INSERT … ON DUPLICATE KEY UPDATE`, BUKAN `FOR UPDATE`) atau kunci baris `SELECT ... FOR UPDATE` (ganti nama merk dan penjaga merk pada penulisan item, `brandKeyGuardStmt`; kunci baris `handovers` di operasi tertentu). Jangan baca lalu tulis tanpa salah satunya. Tes konkurensi memakai `Promise.all` atas permintaan nyata; jangan dilemahkan.
- Kolasi server dan sesi `utf8mb4_nopad_bin`: perbandingan membedakan huruf besar/kecil dan spasi ekor (setara BINARY); kecocokan tak-peka-huruf lewat kolom `key` ternormalisasi (`normalizeKey`/`itemKey` di `shared/`), bukan kolasi. `CHAR_LENGTH` menghitung karakter (emoji = 1), `LENGTH` menghitung byte; pembagian bulat dengan `DIV`; `LOCATE` menggantikan `instr`.
- Migrasi: `server/migrations/NNNN_nama.sql` (urut nama, dicatat di `schema_migrations`). DDL MariaDB TIDAK transaksional (implicit commit): tulis idempoten (`IF NOT EXISTS`) dan hindari DDL non-idempoten; mengubah skema = migrasi baru, bukan menyunting yang sudah diterapkan. Hash migrasi memperbarui templat tes otomatis.
- Tes memakai MariaDB sungguhan lewat tunnel (`bun run db:tunnel`, `QC_TEST_DB_URL` di `server/.env.test`). Harness `server/test-support/`: templat `qc_test_template`; satu skema `qc_test_<epoch>_<hex>` per PROSES `bun test` (dikloning dari templat sekali, dipakai semua berkas di proses itu, dihapus di `afterAll` preload yang berlaku untuk seluruh proses; skema yatim > 6 jam disapu); `createTestEnv` mengosongkan tabel tiap tes dan memberi jam terkendali (`env.clock`) serta jembatan palsu. Pool ≤ 8 koneksi per proses tes (`max_connections` VPS 40, runner ≤ 4 proses). Batas waktu tes 30 dtk (latensi tunnel).
- Konfigurasi: `Env` (`core/env.ts`) = koneksi `DB` + rahasia dari `loadConfig` (`NOW`, `BRIDGE`, `FILE_CACHE` hanya disuntik tes). Jangan membaca `process.env` di luar `config.ts` dan `main.ts`. IP klien lewat `clientIp(request, peerAddress, trustedProxy)` (`http/proxy.ts`): `CF-Connecting-IP` dipercaya HANYA bila peer loopback (nginx); pembatas percobaan salah sync dihitung per IPv4 / per /64 IPv6 (`limiterAddress`; `sync:fails:<id>`, `sync:blocked:<id>`) dan barisnya yang kedaluwarsa dibuang penjadwal tiap jam (`purgeExpiredRateLimits`). Origin publik dan atribut `Secure` cookie diturunkan dari `APP_ORIGIN` (wajib https di produksi), bukan dari header Host; `DEV_LOGIN_EMAIL` ditolak `loadConfig` di produksi atau bila `APP_ORIGIN` bukan localhost. Badan permintaan: JSON REST dibatasi 2 MB (`MAX_JSON_BODY_BYTES`, `http/body.ts`; 413 problem+json VALIDATION; alasan: base64 sudah hilang dari kabel dan muatan JSON sah terbesar < 1 MB, jadi batas kecil memperkecil permukaan serangan memori; keputusan pemilik 2026-11-06), rute biner oleh `maxBytes` masing-masing di `API_ROUTES`, dan batas global `Bun.serve` (`MAX_REQUEST_BODY_BYTES`) = yang terbesar antara rute biner terbesar + overhead kecil dan `/sync` (`SYNC_MAX_BODY_BYTES` 16 MB sampai T25). Semuanya dibaca bertahap (`readTextLimited`/`readBytesLimited`). Tes `http/body.test.ts` mengukur muatan sah terbesar tiap rute JSON; rute JSON baru wajib ditambahkan ke tabel tesnya. Jangan membaca header itu langsung.
- Bentuk kabel item/merk untuk QC Desktop disusun di aplikasi oleh `toWireItem` (`sync/items.ts`, satu-satunya definisi; tanpa JSON di SQL). Mengubah field kabel WAJIB memperbarui `toWireItem` dan tes bentuk kabelnya; perubahan field sinkron item/merk WAJIB menaikkan `sync_rev` (`itemSyncSignature`). Kontrak: `docs/api/desktop-sync.md`.
- Isi berkas dibaca lewat `cachedFileContent` (`core/file-cache.ts`, cache memori LRU 32 MB per proses); izin/folder diperiksa SEBELUM cache; setiap `trashFile`/`replaceFileContent` baru wajib diikuti `dropCachedFile`.
- Runner job (`src/jobs/runner.ts`, poll 2 dtk, satu job pada satu waktu, langkah dikuasai atomik lewat lease) dan penjadwal (pembersihan QR tiap jam) dijalankan `createServer`; `stop()` menunggu putaran berjalan lalu menutup pool.
- Parsing checklist catatan memakai `server/src/modules/handover/checklist.ts` (memo kecil per proses) dan `matchChecksToEntries`; jangan memanggil `extractChecklist`/`matchChecks` berulang per baris.


## Aturan kode GAS (ditegakkan `scripts/build-gas.ts`)
- File di-transpile per file dan `import`/`export` dihapus: semua file berbagi SATU global scope.
- Semua fungsi top-level di `gas/src` WAJIB berakhiran `_` (agar tidak bisa dipanggil via `google.script.run`), kecuali `doGet`, `api`, `setup`.
- Pengecualian terdokumentasi: fungsi murni di `shared/` tidak berakhiran `_` (tidak menyentuh data/API GAS; lihat PRD NFR-2).
- Nama top-level unik di seluruh `gas/src` + `shared/`. Dilarang: `export default`, re-export, import alias/namespace/dynamic, class, enum.
- Tidak ada kode top-level yang memakai global file lain saat load — bungkus dalam fungsi (lihat `getRoutes_`).
- Akses API GAS hanya lewat `platform_()`; implementasi asli di `core/gas-platform.ts`.
- Tulis ke sheet di dalam `platform_().withLock(...)`; teks disimpan lewat `core/db` (aman dari formula injection).
- Performa: tiap panggilan Sheets/Drive berbiaya ratusan ms dan tiap eksekusi Apps Script punya biaya tetap 1,5–2,5 dtk. `handleRpc_`/`handleRpcBatch_`/`handleSync_`/`doGet` membungkus permintaan dengan `withRequestCache_` (cache baca-tabel per permintaan di `core/db`: disalin saat dibaca, dibuang saat tulis lewat `core/db` dan saat masuk/keluar `withLock`) — jangan menulis ke sheet di luar `core/db`. Frontend: `defaultPreload: false` (prefetch hover mengantre RPC `google.script.run` dan memblokir klik nyata); `gas-transport` menggabungkan RPC yang dipicu dalam jendela 15 ms menjadi SATU `api('batch', ...)` (maks. 8 item, tiap item tetap lewat `handleRpc_` penuh; payload > 20 ribu karakter dikirim sendiri), jadi loader yang butuh beberapa query harus memicunya bersamaan (`Promise.all`), bukan berurutan.
- Cache data (server): `readTable_` berlapis — cache permintaan, lalu cache lintas request `CacheService` untuk tabel bertanda `sharedCache: true` di `TableSchema` (brands, customers, qr_defaults, qr_presets — BUKAN users/roles/locations: tabel sumber akses sudah punya cache konteks `uctx`, menumpuk dua cache menunda pencabutan akses hingga ±10 menit; versi per tabel `tblv:<sheet>` diganti saat tulis DAN lagi sesudah `flush` di akhir lock lewat `finishLockWrites_`; TTL 5 menit sehingga suntingan manual di Sheets tampak ≤ 5 menit; > 90 KB tidak di-cache), lalu Sheets dalam SATU panggilan (`getDataRange`). Tulis lewat `core/db` memperbarui cache permintaan di tempat. `setup` memformat semua kolom sebagai teks dan menyetel Script Property `TEXT_FORMATS_V1` (jalankan `setup` setelah deploy); selama belum ada, tulis tetap memformat per baris. Log audit dibaca per halaman (`readAuditPage_`), isi berkas ≤ 540 KB di-cache per potongan di `CacheService` (`fcont:<folderId>:<driveId>`, TTL 3 jam, terikat folder aktif) setelah pemeriksaan izin. Tes yang menyuntik baris mentah ke tabel `sharedCache` harus memanggil `bumpTableVersion_`.
- Cache data (frontend): mutasi QR dan item memasang hasil server langsung ke cache (`web/src/lib/query-cache.ts`: `upsertInList`, `removeFromList`, `markStale`) dan TIDAK menunggu muat ulang (sebelumnya simpan + muat ulang daftar berurutan); `app/prefetch.ts` mem-prefetch daftar yang boleh dibaca sekali saat beranda diam (batch); `app/query-persist.ts` menyimpan query whitelist (me, items, brands, qrcodes) di localStorage per pemilik token, dipulihkan sebelum router dibuat (tampil instan lalu dimuat ulang), dibuang saat keluar. Jangan menambah Log Audit, user, atau isi berkas ke whitelist.
- Jangan pakai API JS yang runtime V8 Apps Script belum tentu dukung (mis. `Object.hasOwn`); aturan Biome `noPrototypeBuiltins` sengaja dimatikan.
- Build menolak API yang TIDAK ada di runtime GAS (`URL`, `URLSearchParams`, `fetch`, `setTimeout`, `atob`/`btoa`, `structuredClone`, `TextEncoder`, `Buffer`, `window`, dll.; daftar + penggantinya di `scripts/build-gas-lib.ts`) di `gas/src` dan `shared/`. Bun/Node/peramban menyediakannya sehingga tes tetap hijau padahal produksi gagal (mis. `new URL` melempar ReferenceError). Gunakan padanan yang disarankan pesan galat.
- Karakter khusus (mis. U+2028) ditulis lewat `String.fromCharCode`, bukan literal/escape di regex.
- Konstanta level atas tidak boleh memakai global file lain (mis. `SYNC_ACTOR`); `verify-dist` memuat semua file `gas/dist` dalam urutan maju dan mundur untuk menangkapnya. Nama top-level harus unik juga terhadap `shared/` (beri awalan modul, mis. `QR_STALE_MESSAGE`).
- Jangan pernah mengedit `gas/dist/` manual.

## Menambah rute REST
1. Tambah id di `WorkerRpcContract` (`shared/rpc.ts`, tipe input/output) dan entri di `API_ROUTES` (`shared/api.ts`: verba, jalur, query, `ifMatch`/`etag`/`create` bila perlu).
2. Validator + handler di `server/src/modules/<modul>/`, daftarkan di `<modul>/routes.ts` dengan `permission` yang tepat; `getRoutes()` bertipe `RouteTable` sehingga typecheck gagal bila id belum terdaftar.
3. FE: `queryOptions`/mutation di `web/src/modules/<modul>/queries.ts` memakai `api(id, input)` (`web/src/lib/api`).
4. Tes REST di `<modul>/rest.test.ts` lewat `restClient`/`restRpc` (`server/test-support`); OpenAPI (`GET /api/openapi.json`) otomatis memuat id baru.
5. Aplikasi GAS lama (`gas/`) hanya dipelihara sampai pensiun (T35); jangan menambah fitur di sana.
6. Modul berlokasi: tandai `scope: 'location'` pada izin rute dan pakai `ctx.locationIds` (lihat `docs/adding-a-module.md`). Izin "salah satu dari": pakai `anyOf` (lihat `docs/adding-a-module.md`).

Resep modul baru: `docs/adding-a-module.md`.
